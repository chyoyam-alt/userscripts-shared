# ✂️ 핀셋 수정 (Crack Pinset) 지침서

> 대상: `scripts/Pinset.user.js` (시험판 0.1.x)
> 이 문서는 두 사람을 위한 것입니다.
> - **사용자**: 이 확프가 무엇을 해 주는지
> - **로컬 테스트 세션(Claude Code)**: 실제 크랙에서 무엇을 확인하고, 문제가 있으면 어디를 고칠지

---

## 1. 이 확프가 원하는 것 (한 줄 요약)

**메시지에서 고치고 싶은 글자만 드래그하면, 그 자리에서 바로 고친다.**
크랙 수정창(⋯ → 수정)을 열고 긴 글 속에서 그 부분을 다시 찾을 필요가 없고, 새로고침도 하지 않는다.
고친 자리에는 **분홍 형광펜 같은 흔적**이 남는다. 원래 글을 다시 보거나 되돌릴 수 있다.

비유하면, 원고 전체를 다시 타이핑하는 게 아니라 **수정테이프와 형광펜**으로 한 단어만 고치는 것.

### 사용자가 하는 일
1. 메시지에서 글자를 드래그한다. 휴대폰은 길게 눌러 선택한다.
2. 선택한 곳 위(휴대폰은 아래)에 작은 막대가 뜬다: **고치기 / 지우기 / 원문**
   - **고치기**: 작은 창에 선택한 글이 들어 있다. 바꾸고 Enter(휴대폰은 [고치기] 버튼)를 누르면 끝.
   - **지우기**: 선택한 부분을 바로 지운다. 알림의 [되돌리기]로 취소할 수 있다.
   - **원문**: 메시지 원문 전체를 연다. 숨김 주석과 `**`, `*` 같은 서식 기호까지 보이고, 선택했던 자리가 미리 잡혀 있다.
3. 고친 메시지 아래에 `✎ 수정 흔적 N` 배지가 붙는다. 배지나 분홍 글자를 누르면 **흔적 창**이 열린다.
   - 고친 기록: 원래 글(취소선)과 바뀐 글(분홍)
   - **방금 것**: 마지막 수정 하나만 되돌림
   - **처음 글로**: 처음 고치기 전 원문으로 되돌림
   - **기록 지우기**: 글은 그대로 두고 흔적만 지움
   - **색칠** 스위치: 분홍 칠 켜기·끄기 (모든 방 공통)
4. 크랙 수정창으로 고친 것도 흔적에 `크랙 수정창`으로 남는다.

## 2. 어떻게 동작하나

### 2-1. 새로고침 없이 바뀌는 이유
크랙 화면은 **메시지 저장소**(zustand)에 든 글을 그대로 그린다. 크랙의 수정 버튼도 이 순서로 저장한다.
저장소를 먼저 바꾸고 → 서버에 PATCH → 실패하면 저장소를 되돌림.

이 확프는 화면 요소의 React 내부 정보(fiber)를 따라 올라가 **크랙이 쓰는 `updateMessage` 함수를 직접 부른다**.
그래서 크랙 수정 버튼을 누른 것과 똑같이 바뀌고, 인증과 토큰 갱신도 크랙이 처리한다.
같은 방식(fiber로 ChatActions 찾기)은 이미 `ELR.user.js`에서 쓰고 있다.

### 2-2. 저장 경로 (위에서부터 시도)

| 경로 | 조건 | 하는 일 | 화면 |
|---|---|---|---|
| **A1** | fiber로 ChatActions와 저장소를 찾음 | `actions.updateMessage({_id, content: 지금 원문}, 새 글)` → `actions.resyncMessage(id)`로 서버 글을 다시 받아 비교 | 바로 바뀜 |
| **A2** | 저장소는 찾았지만 ChatActions는 못 찾음 | 직접 `PATCH` → `GET`으로 확인 → `store.getState().updateMessage(id, {content})` | 바로 바뀜 |
| **C** | fiber를 전혀 못 찾음 (예: Firefox 샌드박스) | 직접 `PATCH` → `GET`으로 확인 | **새로고침해야 보임** (알림에 [새로고침] 버튼) |

- PATCH 주소
  - 스토리: `PATCH https://crack-api.wrtn.ai/crack-gen/v3/chats/:chatId/messages/:messageId {message}`
  - 캐릭터 채팅: `.../crack-gen/character-chats/:chatId/messages/:messageId`
- 성공 판정: 저장 뒤 서버 글(resync 또는 GET)이 우리가 보낸 글과 같아야 한다(끝 공백·줄바꿈 형식은 무시). 다르면 "크랙 서버에 반영되지 않았어요"를 띄운다.
- `updateMessage`에는 오래된 메시지 객체 전체가 아니라 `{_id, content}`만 넘긴다. 크랙은 실패하면 `Object.assign`으로 되돌리는데, 객체 전체를 넘기면 그사이 바뀐 상황 이미지 같은 다른 필드까지 옛것으로 되돌아가기 때문이다.

### 2-3. 고치기 전 안전장치 (하나라도 걸리면 저장하지 않음)
- 다른 방으로 이동했으면 취소
- 답변 생성 중(ChatState.status ≠ `IDLE`, 또는 화면에 `.animate`가 있음)이면 거절
- 그 메시지의 크랙 수정창(tiptap)이 열려 있으면 거절. 열린 창이 옛 글을 들고 있어서, 나중에 저장하면 우리 수정이 덮이기 때문
- 캐릭터 채팅에서 크랙 '수정하기'로 아래 입력창에 글을 불러온 상태(ChatState.isEdit)면 거절. 이유는 위와 같음
- 같은 메시지를 저장하는 중이면 거절 (앞의 저장이 끝날 때까지)
- 저장 직전 저장소의 원문이 처음 읽은 원문과 다르면 거절 ("그사이 메시지가 바뀌었어요")
- 메시지를 전부 비우는 것은 거절
- 고친 뒤 8,000자를 넘으면 편집 창에 경고만 띄운다. 크랙 수정창(tiptap CharacterCount 8000)은 8,000자가 넘는 글을 열면 **앞부분을 잘라 버리기** 때문

### 2-4. 화면 글자 → 원문 위치 찾기 (가장 까다로운 부분)
화면에는 `**굵게**`의 별표나 `[//]: # (…)` 같은 숨김 주석이 보이지 않는다. 그래서 선택한 글자가 원문의 몇 번째 글자인지 따로 찾아야 한다.

0. **메시지 화면 = 그룹 전체**: 그룹 안의 `.wrtn-markdown`을 모두 이어 붙인 글을 화면 글로 본다. 캐릭터 채팅은 답변 한 개를 빈 줄마다 말풍선(.wrtn-markdown) 여러 개로 나눠 그리기 때문이다.
   - 말풍선 하나만 보고 맞추면 앞 문단의 같은 말을 잘못 고칠 수 있다. 0.1.0에서 실제로 있던 문제.
1. **숨김 요소 빼기**: 원래 위치는 기억해 두고 원문에서 잠시 빼 둔다(`stripHidden`).
   - 링크 정의 줄: `[//]: # (…)`, `[//]: <> (…)` 등
   - 이미지 `![](…)`, 링크 주소 부분 `](…)`
   - 줄 앞 목록·인용·제목 기호: `- `, `1. `, `> `, `# `
   - `<!-- … -->`는 **크랙이 글자 그대로 보여 주므로** 빼지 않는다. 다만 화면에 `<!--`가 없으면(다른 확프가 지운 경우) 뺀다.
2. **짝 맞추기**: 화면 글자(TreeWalker로 모은 텍스트, 버튼 글자는 제외)와 원문을 앞에서부터 한 글자씩 맞춘다(`align`).
   - 원문에만 있는 서식 기호와 공백은 건너뛴다.
   - `&amp;` 같은 문자 참조는 한 글자로 친다.
   - 어긋나면 다음 화면 글자 6개를 원문에서 찾아 다시 맞춘다(600자 안). 이때 원문의 글자(기호 말고)를 건너뛰었으면 그 자리를 '점프'로 표시한다.
3. **검증**: 다음 중 하나라도 걸리면 고치지 않고 **원문 고치기 창**을 대신 연다(선택 위치를 대략 잡아 줌).
   - 선택한 화면 글자 중 원문과 짝이 안 맞는 것이 있음
   - 순서가 뒤집힘
   - 선택 안에 '점프'나 문자 참조(`&amp;`), 백슬래시 이스케이프가 있음
4. **바꾸는 규칙**: 선택한 글(보이는 글자와 공백)과 새 글을 **앞뒤로 비교해 실제로 달라진 가운데만** 원문에서 바꾼다(`planSplice`). 그래서 서식 기호는 대부분 제자리에 남는다.
   - 예) 목록 `- 첫째 항목\n- 둘째 항목`에서 `항목 둘째`를 `항목 두번째`로 바꾸면 `둘` 한 글자 자리만 바뀌어 `- 두번째 항목`이 된다.
   - 바뀌는 가운데 안에 기울임·굵게 기호(`*`, `_`, `~`)만 끼어 있으면, 그 기호를 새 글 바로 뒤에 둔다.
     예) `*비가 내리기 시작했다.* 창문에 **빗방울**`에서 `시작했다. 창문에 빗`을 통째로 바꾸면 → `*비가 내리기 멈췄다. 하늘에 햇***방울**`
   - 그 밖의 기호(목록·인용·제목 기호, 링크 주소, 이미지, 이스케이프)가 끼어 있으면 **원문 고치기 창**으로 넘긴다. 블록 구조가 깨지는 것을 막기 위해서다.
5. **지울 때 다듬기** (`tidyDelete`)
   - `*글*`의 글을 통째로 지우면 남는 빈 기호 쌍(`**`, `****`)도 지운다.
   - 기호 바로 안쪽에 공백이 남으면(`*글 *`, `* 글*`) 그 공백도 지운다. 크랙(CommonMark)은 이런 경우 기울임을 풀고 별표를 그대로 보여 주기 때문이다.
6. **답변 비교(재생성) 그룹**: `data-message-group-id`는 그룹 첫 메시지 id다. 실제로 보이는 답변은 다음 순서로 고른다.
   - MessageMarkdown 컴포넌트 props의 `content`와 같은 글을 가진 메시지
   - 캐릭터 채팅처럼 props가 문단 하나뿐이면, 그룹 화면 글과 가장 잘 맞는(coverage 0.9 이상) 메시지
   - 없으면 `selectedMessageId` 규칙
7. **fiber 세대**: 화면 요소에 붙은 fiber는 처음 만들어질 때의 것이라, 위로 올라가다 보면 한 번 전 렌더의 값(alternate)을 만날 수 있다. 그래서 맨 위(HostRoot)가 지금 화면의 것인지 확인하고, 아니면 alternate 쪽 props를 읽는다(`liveProps`).

### 2-5. 흔적 기록
- 저장 위치: Tampermonkey 저장소
  - `cpn:chat:{chatId}` = `{ 메시지id: 기록 }`
  - `cpn:index:v1` = 방별 마지막 사용 시각 (150개 방까지)
  - `cpn:settings:v1` = `{paint}`
- 기록 모양
  ```
  {
    base:    처음 고치기 전 원문,
    current: 마지막으로 확인한 서버 원문,
    spans:   [[시작, 끝], …],   // current 안에서 바뀐 자리. 시작=끝이면 '지운 자리'
    edits:   [{ at, kind: 'pin'|'source'|'native', before, after, prev?, prevSpans? }],
    at
  }
  ```
  - 메시지당 수정 30개, 되돌리기용 `prev`는 최근 10개까지만 둔다. 방당 메시지 120개까지 기록한다.
- 칠하기: 브라우저의 **CSS Custom Highlight API**(`::highlight(cpn-edit)` 분홍, `::highlight(cpn-cut)` 지운 자리 물결 밑줄)를 쓴다. 크랙의 글자 노드는 건드리지 않는다.
- 배지 `.cpn-badge`는 `.wrtn-markdown` **안이 아니라 바로 뒤**에 붙인다.
- 배지는 메시지마다 하나다. 캐릭터 채팅은 마지막 말풍선 뒤에 붙는다.
- 화면 글 ≠ `current`이면 "어긋남"으로 보고 칠하지 않는다. 되돌리기와 처음 글로도 막는다.
- 화면 글 = `base`이면 기록을 지운다(다른 곳에서 원래대로 돌려놓은 것). 단, 다음 경우에는 지우지 않는다.
  - 저장 중, 크랙 수정창 확정 대기 중, 새로고침 대기 중 (`inFlight`, `pendingNative`, `reloadNeeded`)
  - 저장소(store)에서 읽은 글이 아닐 때
  - 이 조건이 없으면, '처음 글로'가 느리게 실패할 때 원래 글 기록이 사라질 수 있다.
- 되돌리기와 처음 글로는 서버 글이 `current`와 같을 때만 실행한다(compare-and-swap). 다른 확프(WRMC, 리롤 믹서 등)가 그사이 바꿨으면 덮어쓰지 않는다.
- 다른 곳에서 바뀐 뒤 다시 고치면 기록을 **거기서부터 새로 시작**한다(`rebased: true`).
  - `base` = 그 시점의 글, `origin` = 맨 처음 원문(보관만)
  - 옛 수정은 흐리게 보기만 하고 되돌릴 수 없다. 남이 쓴 글이 되돌리기로 지워지지 않게 하기 위해서다.
- 여러 탭: 저장할 때 저장소를 다시 읽어 **이 탭이 바꾼 메시지만** 덮어쓴다. `GM_addValueChangeListener`로 다른 탭의 변경도 따라간다.

### 2-6. 크랙 수정창으로 고친 것 잡기
1. `store.subscribe`로 같은 메시지의 글이 바뀌는 순간 전/후를 잠깐 기억한다. 다음 경우는 제외한다.
   - 새 메시지
   - 우리가 방금 쓴 글
   - 생성 중이라도 기억은 한다. 아래 2번처럼 PATCH가 와야 확정되므로, 생성·재생성·resync(PATCH 없음)는 걸러진다.
2. 그 메시지의 `PATCH`가 2xx로 끝나면(XHR·fetch 훅) 확정해서 `native` 기록으로 남긴다.
3. 15초 안에 PATCH가 없으면 버린다. 생성 마무리나 resync 같은 변화가 여기에 걸린다.
4. 다른 확프의 XHR 훅(모바일 유틸 등)과는 원래 함수를 감싸는 식으로 같이 산다.

## 4. 로컬 실기기 점검표

**준비**
- 크랙에 로그인한 크롬에 Tampermonkey로 `Pinset.user.js`를 설치한다.
- **버리는 테스트 방**을 하나 만든다. 서버 글을 실제로 바꾸므로 소중한 방에서 하지 않는다.
- 결과는 항목 번호와 함께 ✅/❌, 그리고 `diag()` 출력이나 콘솔 오류를 남긴다.

### A. 연결 (가장 먼저)
1. 스토리 채팅방에서 `CrackPinset.diag()` 실행 → `fiber`, `actions`, `store`, `chatState`가 모두 채워지는지.
2. 채팅형(말풍선) UI로 바꾼 뒤 1번 반복.
3. 캐릭터 채팅방(`/characters/…/chats/…`)에서 1번 반복. 여기서는 `actions`가 다른 이름일 수 있다. `firstMessage.mds`(말풍선 수)가 문단 수와 같은지, `coverage`가 1 근처인지도 본다.
4. 방을 옮긴 뒤(새로고침 없이) `diag()`의 `chatState.chatId`가 새 방인지.

### B. 핀셋 고치기 (경로 A1)
5. AI 메시지 한 단어를 드래그 → 막대 → 고치기 → Enter.
   - 새로고침 없이 바로 바뀌는지
   - 분홍 칠과 `수정 흔적 1` 배지가 붙는지
   - 네트워크 탭에 PATCH 1번 + GET 1번만 나가는지
6. 새로고침 → 바뀐 글이 그대로인지. 분홍 칠과 배지도 남는지.
7. 고친 메시지를 **크랙 수정창**으로 열기 → 새 글이 보이는지. 그대로 `수정 완료`를 눌러도 되돌아가지 않는지.
8. 다른 방에 갔다가 돌아왔을 때 옛 글이 보이지 않는지.
9. 유저 메시지도 5번처럼 고쳐지는지.
10. 서식 경계를 넘는 선택: `*기울임*` 끝부분 + 일반 글 + `**굵게**` 앞부분을 한 번에 선택해서 고침 → `CrackPinset.records()`와 크랙 수정창으로 원문이 의도대로인지(2-4의 예처럼).
11. 맨 앞에 `[//]: # (…)` 숨김 주석이 있는 메시지의 첫 문장 고치기 → 주석 줄이 그대로 남는지.
12. 같은 구절이 여러 번 나오는 메시지에서 **두 번째** 것을 고치기 → 두 번째만 바뀌는지.
13. 재생성해서 `답변 비교 1/2`가 있는 메시지에서 보이는 답변을 고치기 → 실제로 보이는 답변이 바뀌는지(다른 변형이 아니라).
13-1. 캐릭터 채팅: 앞 문단과 같은 말이 뒤 문단에도 있을 때 뒤 문단의 그 말을 고치기 → 뒤 문단만 바뀌는지. 배지가 메시지에 하나만 붙는지.
13-2. 캐릭터 채팅: 크랙 '수정하기'로 아래 입력창에 불러온 상태에서 같은 메시지를 핀셋으로 고치면 거절되는지.
14. 지우기 → [되돌리기] → 원래대로인지. 기울임 문장의 끝부분, 앞부분, 통째로를 각각 지워서 별표가 화면에 보이지 않는지.
15. 흔적 창 → `방금 것` / `처음 글로` / `기록 지우기` / `색칠` 끄기·켜기.

### C. 원문 대조가 어려운 글 (`CrackPinset.mapTest()`로 결과 기록)
16. 다음 위치를 하나씩 선택해 `mapTest()`를 실행한다. `ok:false`면 원문 창이 대신 열리는지만 확인하면 된다(데이터는 안전해야 함).
    - 링크 `[글](주소)`
    - 인라인 코드 `` `코드` ``, 코드블록(```` ``` ````) 안
    - 표, 목록(`1.`, `-`), 인용(`>`), 제목(`#`)
    - `\*` 이스케이프, `&amp;`
    - 짝 없는 `*`
    - 이미지 바로 앞뒤
    - WRMC가 주입한 블록 근처
17. 상태창 같은 HTML이 들어간 메시지가 있으면 그 근처도 16번처럼 확인한다.

### D. 안전장치
18. 답변이 써지는 중에 이전 메시지를 고치려 하면 거절되는지.
19. 크랙 수정창을 열어 둔 채 같은 메시지를 핀셋으로 고치면 거절되는지.
20. 네트워크를 끊고(DevTools Offline) 고치기 → 실패 알림이 뜨는지. 화면 글이 원래대로 돌아오는지.
21. 8,000자 가까운 메시지에서 글을 늘리면 경고가 뜨는지.
22. 프롤로그(첫 메시지) 고치기 → 서버가 받아 주는지. 안 되면 오류 문구 기록.

### E. 크랙 수정창 기록
23. 크랙 수정창으로 한 단어를 고치기 → 배지가 생기고 흔적 창에 `크랙 수정창`으로 남는지(`diag().nativeCaptured` 증가).
24. 재생성, 이어서 생성, 상황 이미지 생성 뒤에 **엉뚱한 `크랙 수정창` 기록이 생기지 않는지**.
25. 크랙에서 메시지를 삭제하면 그 기록도 사라지는지.

### F. 화면·조작
26. 휴대폰(또는 DevTools 모바일 모드)에서 길게 눌러 선택 → 막대가 기본 복사 메뉴와 겹치지 않는지. 고치기 창이 아래쪽 시트로 뜨는지.
27. crack-mobile-utility의 길게 누르기 메뉴와의 충돌. 켜져 있으면 선택이 안 되는 것이 정상이다(6장). 끄면 26번이 되는지 확인한다.
28. 편집 창에서 Enter, 한글 조합 중 Enter, Esc가 크랙 단축키(입력창 이동 등)로 새지 않는지.
29. 다크/라이트 테마에서 막대, 창, 배지, 분홍 칠이 잘 보이는지.
30. 긴 방(메시지 200개 이상)에서 스크롤과 타이핑이 버벅이지 않는지. 흔적이 많은 방에서 특히 확인.

### G. 다른 확프와 같이 쓰기
31. WRMC, LogShift, RerollMixer가 같은 메시지를 바꾼 뒤 → 배지가 "어긋남"이 되는지. 되돌리기가 막히는지(덮어쓰지 않아야 함).
32. ELR, INFO HUD, 갈래 매듭과 같이 켜고 오류가 없는지.

## 5. 문제가 나오면 어디를 보나 (로컬 세션용)

| 증상 | 볼 곳 |
|---|---|
| `diag()`에서 actions/store/state가 `null` | `findBridge`, `isActions`, `isChatState`, `isStore` |
| 엉뚱한 답변(재생성 변형)이 바뀜 | `messageOf`: props 탐색 깊이, `messageIds`, `selectedMessageId` |
| 선택한 곳과 다른 곳이 바뀜 / `mapTest` 결과 이상 | `stripHidden`(숨김 규칙), `align`(재동기화 600자·6글자), `mapSelection` |
| 저장은 됐는데 화면이 안 바뀜 | `sendContent` A1 뒤 `resyncMessage`. A2의 `store.getState().updateMessage` |
| 엉뚱한 `크랙 수정창` 기록 | `watchStore`(제외 조건), `onPatchDone`, `ownWrites` 시간(30초→2초) |
| 칠이 어긋남 | `rangesFor`(spans→화면 위치), `shiftSpans` |
| 막대가 안 뜨거나 늦게 뜸 | `checkSelection`, `currentSelection`, `pointerHeld` |
| 지운 뒤 별표가 보임 / 서식이 깨짐 | `planSplice`(가운데만 바꾸기, 기호 검사), `tidyDelete` |
| 캐릭터 채팅에서 엉뚱한 문단이 바뀜 | `mdsOf`(그룹 전체), `messageOf`의 coverage 고르기 |

시험용 가짜 크랙 화면(Playwright)은 `tests/pinset.mock.js`에 있다(`npm i -D playwright` 후 `node tests/pinset.mock.js`, 경로 C는 `NOFIBER=1`). 스크린샷은 `tests/out/`에 남는다.
여기에는 메시지 저장소, ChatActions, fiber 흉내가 들어 있다. 실기기에서 다른 점이 나오면 이 가짜 화면도 맞춰 고치면 된다.

## 6. 알려진 충돌

- **crack-mobile-utility의 '메시지 길게 누르기 메뉴'**(기본으로 켜짐)를 쓰면, 휴대폰에서 메시지 글자를 선택할 수 없어서 핀셋 막대가 뜨지 않는다.
  - 이 확프가 메시지 글자에 `user-select:none`을 걸고, 길게 누르면 자기 메뉴를 띄우기 때문이다.
  - 휴대폰에서 시험하려면 그 설정을 끄면 된다.
  - 다음 단계 후보: 크랙 ⋯ 메뉴나 CMU 메뉴에 '핀셋/원문 고치기' 항목 넣기.

## 7. 아직 안 넣은 것 (다음 단계 후보)
- **AI로 다시 쓰기**: 선택 부분만 AI에게 고쳐 달라고 하기. 크랙에는 부분 재작성 API가 없어서 외부 AI 키가 필요하다(`GM_xmlhttpRequest`, `@connect`).
- **크랙 수정창 자동 조작(경로 B)**: 메뉴 → 수정 → tiptap `setContent` → 수정 완료. fiber가 아예 안 될 때의 대안이지만 8,000자 자르기 위험 때문에 보류했다.
- 지운 자리를 더 잘 보여 주기: 지금은 옆 글자에 물결 밑줄만 긋는다.
- 수정 하나만 골라 되돌리기: 지금은 마지막 것이나 전체만 된다.
